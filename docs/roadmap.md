# 落地路线：指定区域内自动生成可行焊接路径

> 这份文档回答一个问题：**工件放在指定区域里，怎么稳定地规划出可行、无碰撞、
> 可执行的接近/焊缝/退刀路径**——并说明每条路线要学什么、在本仓库哪里实现、
> 用什么命令验收。
>
> 读者：项目主人（边学边做）。写于 2026-10-22，基于当时的真实测试数据。

---

## 现状更新（2026-10-23）

- 默认链已从「直线 → RL → OMPL」改为 **「直线 → OMPL」**，理由是数据：
  266 条真实请求里 94% 的直连路径无碰撞（直线 3 ms 可解），剩下 6% 需要绕行，
  而 RL 在全难度上只有 0~10%——放进默认链只增加延迟。
- `rl` / `hybrid` 保留为实验入口（UI 标注"实验"），不影响落地链路。
- 详见 `docs/rl_bench.md` 末节。

## 0. 先把"落地"拆成可验收的小目标

"落地"不是"能跑一次"，而是**在工件位置有不确定性的情况下，仍然稳定成功**。
所以验收指标是这三个，缺一不可：

| 指标 | 含义 | 当前状态 |
| --- | --- | --- |
| 成功率 | 随机工件位姿 × N 次，成功次数 / N | **未知**（只在固定位姿上验证过） |
| 安全性 | 执行轨迹逐点 FCL 无碰撞 + 关节限位/速度合规 | 接近段有校验；焊缝段有逐点校验 |
| 可复现 | 同一请求同一条路径（确定性） | 焊缝段是；接近/退刀段的 OMPL 不是 |

**M1 的任务就是把这个"未知"变成数字。**

---

## 1. 现在真实会什么、不会什么（别被历史数字误导）

| 能力 | 证据 | 结论 |
| --- | --- | --- |
| 工件导入 + 边提取 + 焊缝拼装 | 单缝 33.6 s、同缝两次 75.2 s、21 次反向 | ✅ 可用 |
| 焊缝段确定性执行 | 50 ms 均匀网格 + 双 S 时间参数化 | ✅ 可用且可复现 |
| 接近/退刀：直线优先 | `auto` 分母，Δq=0.3 时 3 ms 出解 | ✅ 可用 |
| 接近/退刀：OMPL 兜底 | 不可行目标返回 -27，节点存活 | ✅ 可用 |
| **RL 避障** | 30 个"直线穿工件"场景：**0/30 到达**，4~26 次碰撞 | ❌ **不可用** |
| RL 无遮挡短段 | 真实场景 + 真实起点：100%/0 碰撞 | ⚠️ 可用但没优势（直线 3 ms 更快） |

结论：**落地基线只能是"直线 + OMPL"，RL 现在不能承担避障**。想让它承担，
必须先解决第 4 节的问题。

## 2. 三条路线（可组合，不是三选一）

### 路线 A：确定性几何（落地基线，风险最低）

```
工件位姿 → 焊缝起点/终点 → IK 求接近位姿
        → 直线（可复现） 失败 → OMPL（几何保证）
        → 逐点 FCL 校验 + 时间参数化（双S）
        → 执行
```

- 代码位置：`src/rosim_planning/src/line_planner.cpp`（直线）、
  `planning_node.cpp::makePlanner`（`auto` 链）、`edge_follower.cpp`（三段）
- 要学：**IK 多解与分支跳变**（为什么直线会失败）、**OMPL 的 RRTConnect 采样**、
  **TOTG/双S 时间参数化**、**碰撞检测的空间换时间**
- 风险：工件位姿变化大时，IK 分支跳变会让直线失败率高 → 靠 OMPL 兜底，但耗时会上升
- 验收：`python3 scripts/benchmark_suite.py`（free/long/blocked 三组）+ 随机工件位姿基准

### 路线 B：纯学习型（研究分支，不阻塞落地）

```
观测(关节+目标+最近距离) → PPO 策略 → 每步 0.1 rad
                          ↓
                    FCL 逐步校验（不安全就丢弃）
```

- 代码位置：`rl_a/env.py`（环境）、`rl_a/train.py`（训练）、
  `src/rosim_rl/src/rl_remote_planner.cpp`（接进规划链）、`scripts/rl_plan_node.py`（策略服务）
- 要学：**观测设计**（为什么加最近距离）、**奖励整形**（进度/碰撞/边距）、
  **课程学习**、**分布偏移**（训练起点 vs 真实起点——本项目踩过两次）
- 现状阻塞点：**"绕过去并到达"学不出来**（见第 4 节）
- 风险：调参周期长、结果不稳定；**不能作为唯一规划器**

### 路线 C：混合（落地的最终形态，推荐）

两个可行的混合方式，按可靠性排序：

**C1. 几何主导 + 学习加速（推荐先做）**
```
OMPL/直线 出可行几何路径（保证成功）
   ↓
RL 只在"已验证无遮挡的短段"里做路径缩短/速度优化
   ↓
结果再由 FCL 校验，不通过就退回原路径
```
- 失败模式：RL 只会让路径变差 → 校验后丢弃，**永不劣化**
- 收益：路径更短/更平滑（有可量化指标：路径长度、执行时间）
- 代码位置：新建 `src/rosim_planning/src/shortcut_planner.cpp`（装饰器）

**C2. 学习主导 + 几何修复（研究目标，暂缓）**
```
RL 出初解（可能不可行）
   ↓
OMPL 做 repair：把碰撞段替换成局部可行段（类似 CHOMP/STOMP 的"接回"）
   ↓
不修复成功就整段放弃，用 A 兜底
```
- 前提：RL 在挡路场景的到达率 > 0（现在 0/30，所以 C2 暂时没有输入）

## 3. 里程碑（每个都能独立验收）

### M1. 随机工件位姿基准（最高优先级，1 天）—— **已完成第一版**

**结果（2026-10-22，8 个随机位姿，规划器 auto）**：成功 **7/8 = 87.5%**，
每个位姿 34~40 s（含导入、接近、沿缝、退刀）。失败的那一个 2 s 内返回，
说明是接近段直接失败（待归类原因）。

区域（按你给的）：x ±1.40（轨道全长）、y ±0.5~±1.5、z −0.2~0.8、yaw 任意，全部相对底座。
可达性普查（按最优导轨位置）：**85.9%** 在臂展 1.40 m 内；|y| 0.5~1.1 为 **100%**，
|y| 1.1~1.5 只剩 **64.9%**。所以基准只取"舒适区"（距底座 ≤1.05 m）。

命令：`./scripts/workpiece_bench.sh 8 auto`

**做什么**：加一个基准：把工件随机放在指定区域内 N 个位姿，每个位姿跑一遍
"导入 → 求缝 → 接近 → 沿缝 → 退刀"，统计成功率/耗时/失败原因分布。

**为什么先做这个**：这是"落地"唯一可信的指标，也是后面所有优化的对照基线。
没有它，任何改进都无法判断是否真的更好。

**验收**：`python3 scripts/workpiece_bench.py --poses 20` → 输出成功率表格
和失败原因 top3（IK 失败 / 直线碰撞 / OMPL 超时 / 不可达）。

### M2. 工件区域参数化 + 可达性预判（1~2 天）

**做什么**：把"指定区域"变成配置（`x∈[…], y∈[…], yaw∈…`），并在导入时
预判该位姿是否可达、焊接姿态是否需要翻转，不可达就在界面上直接提示，而不是
等到规划失败。

**要学**：工作空间分析（可达性/灵巧度）、IK 分支选择、工具姿态与碰撞的耦合。

**验收**：给一个明显超出范围的位姿，界面 3 秒内给出"不可达 + 原因"。

### M3. 接近/退刀路径质量优化（2~3 天）

**做什么**：直线失败率高的位姿现在只能靠 OMPL（500 ms 级、不可复现）。
加两个改进：
1. **分段直线**：先沿工具轴退到安全高度，再走世界系直线（模拟焊工动作）；
2. **OMPL 结果后处理**：路径短路（shortcut）+ 平滑，降时间、提可复现性。

**验收**：同一批位姿，接近段中位耗时下降 ≥30%，且路径长度不变差。

### M4. RL 在可验证的子问题上发挥作用（3~5 天，可失败）

**做什么**（按投入产出排序）：
1. 先量化"RL 有没有价值"：在同一批 **无遮挡** 短段上，比较 `line` vs `rl` 的
   路径长度/执行时间。若 RL 不占优，直接停在这里，不再投入。
2. 若占优，扩到 C1：RL 只做短路优化，结果 FCL 校验。

**要学**：如何设计"可证伪"的实验（对照组、指标、显著性），而不是看训练曲线。

**验收**：一张表，明确回答"RL 在哪个子问题上比几何方法更好，好多少"。

### M5. 系统化（持续）

- 每次规划记录 `planner / 耗时 / 路径长 / 最小间隙 / 失败原因`（现在部分有）
- 回归脚本：固定位姿 + 随机位姿两套，改动前后对比
- 参数集中到 launch/yaml，不再散落在代码里

## 4. 如果想让 RL 真正学会绕障（研究问题，先把预期说清）

现在的失败点很具体：**碰撞降下来了（15~26 → 4），但到达仍是 0/30**。原因大概率是：

1. **奖励是稠密进度 + 稀疏到达**：绕行时"进度"会先变负（先远离目标），
   策略学到"远离=坏"，于是选择停下（超时）而不是绕行。
2. **探索不足**：绕行需要连续 10~20 步朝"暂时变差"的方向走，PPO 的随机探索
   很难撞上；
3. **观测不含障碍几何**：现在只有 30 个包围球的距离，策略不知道"往哪边绕"。

三个可行的改法（按性价比排序）：

| 改法 | 做法 | 预期 |
| --- | --- | --- |
| **参考路径引导** | 训练时先用 OMPL 生成一条可行路径，把"沿参考路径的进度"作为奖励主项 | 学会跟随绕行，收敛快 |
| **观测加方向信息** | 观测里加"障碍相对目标的方位"，或直接用 3D 栅格/点云特征 | 知道往哪绕 |
| **课程学习** | 遮挡从 5 mm 逐渐加深到 40 mm，成功一档再进下一档 | 稳定爬坡 |

这三条都还没做，**预计每轮 15~25 分钟训练**，需要 2~4 轮迭代才能看到是否可行。

## 5. 建议的执行顺序（我的推荐）

```
M1（基准）  →  M2（区域+预判）  →  M3（路径质量）  →  M4（RL 子问题，可失败）  →  M5（系统化）
                                                              ↑
                                              第 4 节的三个改法只在这里投入
```

理由：
- M1 让"好不好"变成数字，避免再出现"自己评估 97.5%、实际一半碰撞"这类误判；
- M2/M3 直接提升落地成功率，收益确定；
- M4 明确设"可失败"检查点（先量化 RL 有没有价值），不再盲目烧训练时间；
- 第 4 节的研究放在 M4 里，只有当前面的实验证明 RL 有价值才继续。

## 7. 需要你拍板的三件事

1. **工件"指定区域"的实际范围**（x/y/z/yaw 各多少）——M2 要按它写参数；
2. **验收门槛**：成功率多少算"能落地"（例如 20 个随机位姿成功 ≥ 18）；
3. **RL 的定位**：只当研究分支（不阻塞落地），还是必须进入产线默认链路。
   我的建议是前者，等 M4 的量化结果再决定。
